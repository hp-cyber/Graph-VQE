Graph independent VQE matched benchmark

55 proteins x 2 shot settings x 3 optimizers x 2 entanglement patterns = 660 jobs.
Each job runs one protein and only IndependentSubspaceVQE. The two standalone
Graph-VQE strategy directories use the same nearest-neighbor global ansatz.
Their common strategy code is in sources/independent-vqe, with campaign adapters in tools.
The copied base modules include utilities; they do not schedule other strategies.

Settings
  shots=-1: analytic MPS expectation, no sampling or dense-state readout.
  shots=1000: 1000 samples for energy estimation and 1000 final readout samples.
    Includes sampling fluctuations; no additional gate or measurement-error model.
  Optimizers: COBYLA, L-BFGS-B (lbfgs), SPSA.
  Entanglement: linear / reverse_linear, four repetitions, in both stages.
  Hamiltonian coefficient graph -> local partitions of at most 12 qubits.
  Optimize each partition once. Map its best rotation parameters into the full
    circuit by layer, physical qubit and rotation gate. This transfers parameters;
    it does not embed the exact tensor product of the optimized local states.
  Then optimize one full-register nearest-neighbor SU2 circuit once, against
    every term of the original Hamiltonian. There are no extra graph-edge gates.
    The global parameter count is n*(reps+1)*2, or 970 for 97 qubits at reps=4.
  Stop at the first consecutive energy change |delta E| < 1, no patience/window.
    This is the matched benchmark stopping rule. COBYLA/L-BFGS compare objective
    calls (excluding derivative probes); SPSA compares successive updates.
    Optimizer convergence or the numerical budget can also end a solve.
  Default numerical budget: 1,000,000 (COBYLA objective calls; L-BFGS iteration/
    function limits; SPSA updates). --max-iter is mainly useful for smoke tests.

Acceleration and exactness
  Backend: tensornet-mps-mqpu-shots. Analytic mode uses shared Pauli-prefix
  contractions; diagonal sampled energies reuse a shared measurement stream.
  Absolute and relative SVD cutoffs are zero. Each local/global circuit uses
  min(2**reps, 2**floor(width/2)): bond 16 at 97 qubits, bond 8 at 7 qubits.
  The cap covers every intermediate state of these nearest-neighbor circuits;
  floating-point roundoff remains. The backend rejects resolved truncation.

  L-BFGS differentiates both stages with reverse-mode MPS contractions in CUDA
  PyTorch. No parameter-shift loop or finite-difference fallback is used for
  campaign L-BFGS. For 1000 shots this is a HYBRID estimator: analytic gradients,
  sampled objective values and sampled final readout.
  SPSA uses two perturbation evaluations per update plus its objective evaluation,
  five calibration pairs, and the same accelerated backend for every evaluation.

  The previous global ansatz added R_ZY/R_YZ gates on Hamiltonian graph edges.
  That ansatz and its memory estimates are obsolete. Existing checkpoints from
  it cannot resume into the new nearest_neighbor_su2_v1 parameter layout.
  The Hamiltonian still determines partitions; no Hamiltonian term is discarded.
  See MEMORY.txt for scheduling, host safety, process cleanup and allocation checks.

Run on this server (full campaign is not started by installation)
  cd /home/fengy46/Graph-VQE/test
  ./run.sh --dry-run
  ./run.sh

Default scheduling: GRAPH_VQE_GPUS if set (this server: 2,3,4,5,6 in its local
campaign_storage.env), otherwise every GPU nvidia-smi lists. Jobs start one at a time while the host stays
responsive and the GPU's CPU socket has room; at 90% RAM all jobs stop and resume
later (MEMORY.txt). A job uses one GPU for its sequential local solves and global
solve. To choose GPUs:
  GRAPH_VQE_GPUS=0,1,2,3 ./run.sh        (or ./run.sh --gpus 0,1,2,3)

Filters (comma separated, combinable)
  ./run.sh --proteins 3ckz,1e2k --optimizers cobyla,lbfgs,spsa
  ./run.sh --shots=-1,1000 --entanglements linear,reverse_linear
  ./run.sh --proteins 3ckz --max-iter 3 --output validation/my_smoke

The immutable job templates are in jobs/shots_*/optimizer/pattern/protein/job.json.
campaign.json is the scheduling source; use --proteins to select proteins.
Results default to runs/ with the same hierarchy. Validation uses a separate
validation/ directory, so the full campaign starts clean.

Ctrl+C terminates this scheduler's children. Rerunning skips completed cases and
resumes unfinished solves from the latest persisted objective parameters.
Completed local solves are reused, with their best parameters. Pending global
solves restore global candidates and the latest global parameters. SciPy rebuilds
its internal optimizer state; SPSA additionally restores saved RNG/gain/update
state. This is a warm restart, not a promise of an identical uninterrupted path.
Changing shot/optimizer/pattern settings requires a different output directory.
Each case and campaign directory is locked to prevent duplicate concurrent runs.

Recorded per case
  protocol.json: protein, mode, optimizer, settings, target, stopping, GPU,
    backend manifest/checksums and strategy source checksum.
  partition.json: partition/crossing structure and local/global parameter counts,
    written before optimization so it is available even if the job fails.
  optimization_trace.jsonl: objective/probe parameters and counts, energy, timing,
    optimizer starts/restarts, accepted iterations with energy and duration.
    iteration_tail is explicitly incomplete when stopping before a callback.
  *_evaluations.jsonl: optimizer-specific counters/timings, gradients/calibration.
  backend_evaluations.jsonl: CUDA-Q call durations, parameters, shots.
  System_Energy/*.csv: local/warm_start/global energy calls; appended on resume.
    The common journal is authoritative for optimizer iteration timing.
  solves/*.json and optimizer_states/*.json: latest/best parameters, solve state.
  state.json, final_parameters.npy, energy_summary.json: final best state and
    partition metadata, parameter count, local/global summaries.
  readout.json and Structures/*.xyz: only for shots=1000.
  job_status.json: complete only after all required exports succeed.
  run.log: optimizer progress and failures.

Install on another server
  git clone the repository (or copy test/ without runs, validation, admission and
    campaign_storage.env, which hold this server's paths).
  Create and activate cudaq-env (Python 3.11, conda CUDA 12.x, mpi4py/openmpi,
    compilers, m4/autoconf/automake/libtool, flex/bison, pip cudaq, numpy, scipy,
    CUDA-enabled torch, matplotlib, pandas, qiskit, qiskit-ibm-runtime,
    qiskit_algorithms). setup_local_cudaq.sh installs the remaining opt_einsum and
    networkx into it.
  cd test
  ./setup_local_cudaq.sh          (builds CUDA-Q and the backend into test/cudaq_local; hours)
  ./run.sh                        (inside tmux; every GPU, records under test/runs)
  Optional: GRAPH_VQE_GPUS=0,1,2,3 to use only some GPUs; copy
  campaign_storage.env.example to campaign_storage.env to keep records on another
  disk or share the scheduler with other launchers.

The installer matches /home/fengy46/VQE_Docking_cudaq_tensornet-mps/setup_local_cudaq.sh,
plus the opt_einsum/networkx install step. Either copy
builds relative to its own directory, bundles all four backend sources, checks
gradient dependencies, installs a manifest with library checksums, and tests
changing local/global register widths. It does not need the old server's paths.
CUDAQ_LOCAL and GRAPH_VQE_PYTHON override discovery. The application's gradients
live in tools/, not in the backend library. An existing custom backend install
can be shared by sourcing its activate_local_cudaq.sh before this runner.

Validation
  source environment.sh
  "$GRAPH_VQE_PYTHON" -m unittest discover -s tests -v
  "$GRAPH_VQE_PYTHON" tools/validate_graph_gradients.py --gpu 0
  "$GRAPH_VQE_PYTHON" tools/validate_resume.py --gpu 0 --shots -1
  "$GRAPH_VQE_PYTHON" tools/validate_resume.py --gpu 0 --shots 1000
  "$GRAPH_VQE_PYTHON" tools/check_largest_graph.py

Resume validation expects fresh validation/resume/ case directories. Gradient
checks use real seven-qubit local/global circuits with generic rotation angles,
independent dense references and native parameter-shift energy differences.
check_largest_graph evaluates the 97-qubit circuit, checks all reverse gradients
are finite and three against parameter-shift, and performs 1000-shot readout.
Installer tests verify shell/Python syntax and deterministic extraction/migration;
they do not build CUDA-Q. A clean-server build must be tested on that server.
